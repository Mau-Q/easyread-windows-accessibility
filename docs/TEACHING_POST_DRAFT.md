# 揭榜适配-姓名-视障友好适配

教师验收已登记为完成（2026-11-21）。

我选了 Windows 桌面路线，在已有的 EasyRead 文献阅读项目上做视障友好适配。项目基于 [Edwardxlai/easyread](https://github.com/Edwardxlai/easyread)，保留原 MIT 许可和第三方许可。源码和测试在 [课程仓库的 Windows 适配分支](https://github.com/Mau-Q/easyread-windows-accessibility/tree/windows-accessibility)。

我保留了原来的 Python 服务、Web 界面和 Tauri 桌面壳，按任务书和《Windows 应用无障碍开发指南》检查文献导入、阅读、批注和问答。

## 改动

- Windows 构建、Python 环境发现、桌面启动握手、外部链接、窗口退出和所属后台进程清理；修复 Windows 上导致 PDF 正文空白的 JavaScript 模块 MIME 问题。
- 给输入框、图标按钮、可编辑字段、列表、状态和正文 iframe 补齐可访问语义；列表读屏选中与实际选中一致。
- 补齐分类、菜单、设置、模型名单、删除确认和会话管理的键盘操作。弹窗限制背景操作，进入和退出恢复合理焦点。
- F6/Shift+F6 往返工具栏、PDF/网页正文和面板；选文后 Shift+F10 调用批注；摘要、批注和报告引用定位后设置正文焦点。
- 支持系统高对比度颜色、可见焦点，并修复常规主题低对比度文字及低缩放页码不一致。

测试于 2026-11-13 和 2026-11-21 在 Windows x64（10.0.26300）本机进行，使用 Python 3.12.10、Rust/Cargo 1.100.0、Build Tools 2022、WebView2 157.0.4341.46、NVDA 2026.3.1 portable。使用独立数据目录和测试账号，没有接入个人文献。合成两页双栏 PDF、公开 BERT 论文和 arXiv 2411.00640v1 为测试样本。

## 实测结果

| 检查 | 结果 |
|---|---|
| 回归与构建 | Windows Python 235 项在管理员环境下全部通过，包含之前受系统权限限制的符号链接用例。Node 30 项、Rust 3 项及桌面构建通过 |
| 实际桌面核心流程 | 登录、导入、中文题名搜索、列表、PDF、翻页、笔记手动保存和返回通过；另完成分类、模型设置、删除取消/确认、布局缩放、批注、历史与异常恢复 |
| 原生文件操作 | 用键盘在 Windows 文件对话框里导入公开 PDF，再把历史记录另存到 D 盘并确认 JSON 能正常读取 |
| 读屏 | 实际 NVDA 输出包含按钮名称与角色，合成双栏两页共 20 段顺序正确。BERT 连续阅读的语音日志包含摘要、引言与相关工作 |
| 系统高对比度 | 应用 Windows“夜空”主题后检查文字、边框、选中状态和键盘焦点，测试结束后恢复原主题 |
| 自动无障碍检查 | axe-core 在文献库、导入、六个设置页、PDF、笔记共检查 10 个界面状态，未发现规则违规。需要人工判断的项目留在测试记录里 |
| AI 相关状态 | 本地 Qwen 真实生成报告、完成带引用问答与 PDF 聊天并返回选词译文。失败、重试、仅保存和中断用预设响应测试 |
| 图片问答 | 本地视觉模型区分两张合成图的颜色，PDF 问答保存了图片和回答 |
| PDF 重排 | 锁定的 Zotero worker 已生成候选包，合成两页 20 段全部匹配 |

最初测试时遇到 PDF 正文空白、缩放后页码报错和弹窗内菜单焦点异常。修复后重新在 Windows 桌面复测。完整的修复记录和复测命令见 [Windows 测试记录](WINDOWS.md)。

从仓库根目录运行 `start-desktop.cmd`，默认数据在检出目录下 `runtime/windows-dev`。桌面程序依赖源码和 Python 环境。仓库提供测试脚本和样本生成器。

当前读屏记录覆盖合成双栏样本和 BERT 的部分章节。复杂公式、表格和长文仍需人工听读。HJFY 原生 PDF 翻译需要可独立启动的 Windows 引擎。
